Question 6

Knowledge Boundary - Yes, external knowledge is needed: answers must come from Meridian's own 740 SharePoint policy PDFs (infection control protocols, referral procedures, equipment maintenance schedules), which no model was trained on, so this is the pillar that most definitively rules out the Basic Chatbot, because a chatbot answering only from training data would produce plausible but invented policy content. Logic Depth - No: each administrator query is a single retrieve-then-answer step (find the current approved policy passage and summarize it), with no multi-step reasoning, tool calls or actions on other systems, so an orchestrated agent is not needed and the RAG Agent stays in the tree. Memory Lifetime - No: each policy lookup is a standalone question that does not depend on what an administrator asked in a previous session, so a stateless pattern is sufficient and no conversation history needs to be stored. Tracing the elimination tree (Basic Chatbot out at Knowledge Boundary, orchestrated agent not needed at Logic Depth, stateful architecture not needed at Memory Lifetime), the recommended pattern is a stateless RAG Agent: Azure OpenAI Service grounded on an Azure AI Search index of the cleaned, Approved-only policy library, citing the source policy and its effective date in every answer.
