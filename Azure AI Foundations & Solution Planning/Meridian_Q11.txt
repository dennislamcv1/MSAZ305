Question 11

In Workflow A, Azure AI Document Intelligence (a custom template model trained on Meridian's standard intake form and deployed in an EU region) processes each of the 4,200 daily scanned forms first and produces clean, structured output: JSON containing the four labelled fields (patient name, date of birth, insurance ID and presenting complaint), each with a confidence score. That output goes next to a validation step that checks field formats, sends low-confidence fields to clinic staff for review, and writes the confirmed fields to the patient record in Dataverse, so any reasoning model added later (for example Azure OpenAI Service summarizing the presenting complaint) receives only the validated, minimum fields it needs and never the raw scan. The governing principle is that raw sensory data must be sanitized and structured before it enters a language model's context window; if the sequence were reversed, the full scanned page, with every patient identifier, handwritten note and signature on it, would be exposed directly to the model's processing pipeline (prompts, context and logs) before any data handling controls such as field extraction, validation, masking or minimization were applied, breaking GDPR data minimization and leaving Meridian unable to control or audit where that PHI goes. Recommendation: make Document Intelligence the only entry point for scanned forms and Dataverse the hand-off point, and give no language model direct access to the raw scan storage.
